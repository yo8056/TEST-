# 客人資料製作

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一格都要寫「理由」。
> 填好之後，AI 每次幫你做客人都會照這份規則，不用你每次重講。

## 什麼時候用

使用者說「幫我做一批新客人」「我要出題考同學」時。

## 每位客人必須有這些欄位

| 欄位 | 意思 | 限制 |
|---|---|---|
| name | 名字 | 不可用真實名人、不可重複 |
| intro | 一句話介紹 | 20 字以內 |
| budget | 一餐的總預算 | 30～150 的整數 |
| wants | 想吃的東西，有先後順序 | 1～2 樣，只能從菜單選 |
| hates | 討厭的東西 | 最多 1 樣，沒有就寫 null |
| days | 出現在第幾天 | 1～5 的整數陣列，例如 [1, 3] |
| count | 當天的基本人數 | 1～12 的整數 |
| lines | 五種情況的台詞 | 每句 20 字以內，五句都要有 |

`lines` 的五種情況：

- `bought`：買到了
- `hated_on_menu`：討厭的東西有上架，不進門
- `not_on_menu`：想吃的沒上架
- `sold_out`：想吃的賣完了
- `too_expensive`：太貴不買

## 菜單（只能從這六樣選）

招牌鍋貼、韭菜鍋貼、玉米鍋貼、酸辣湯、豆漿、紅茶

## 這批客人的主題

★ 主題：夜市觀光客——逛夜市路過鍋貼店的各種客人（背包客、情侶、帶小孩的爸媽、挑嘴的美食部落客……）
★ 理由（為什麼選這個主題？）：夜市的客人來自四面八方，預算和口味差很多，同一份菜單很難討好所有人。店長必須看預告、做取捨，不能每天用同一套備貨。
★ 補充要求：以現有客人包為基礎，將「挑嘴部落客」的忌口改成玉米鍋貼。拒絕進門台詞同步改成「有玉米鍋貼，我先走。」其餘欄位與其他客人保持原樣。

## 預算範圍

★ 這批客人的預算要落在幾元到幾元之間（必須在 30～150 之內）：45～120 元
★ 理由：下限 45 元的客人買不起任何鍋貼，只能靠湯和飲料賺他的錢；上限 120 元買得起一份鍋貼加一杯飲料，但買不起兩份建議售價的鍋貼。預算壓在建議售價邊緣，店長的定價才有差別（龜毛但公平）。

## 工作步驟

1. 先讀 `web-lab/src/game/menu.js`，確認菜單與建議售價
2. 先產生 3 位客人，用表格給使用者看，**不要直接寫檔**
3. 使用者說 OK，才寫入 `web-lab/src/game/customers/my-customers.json`（整個檔案是一個陣列）
4. 寫完執行下面的檢查，逐條回報結果

## 寫完必須檢查

- 必填欄位都有，五句台詞都有
- budget 在 30～150 之間，也在上面填的預算範圍內
- wants、hates 只用菜單上的品項
- 沒有重複的名字
- 每一天的 count 加總不超過 50
- 在 `web-lab` 資料夾執行 `npm run check`，確認「客人包檢查」仍然全部 PASS
- 打開遊戲，在「客人包」選「我的客人包」，確認沒有出現紅色錯誤
- ★ 我自己加的檢查規則：每位客人的 budget 必須 ≥ 他第一樣想吃的菜（wants 的第一項）的最低可定價；而且 hates 不可以出現在他自己的 wants 裡
- ★ 這條規則要擋掉什麼樣的客人：不管店長怎麼定價都不可能成交的客人。例如預算 45 元卻只想吃玉米鍋貼（最低只能賣 60 元），或是想吃韭菜鍋貼卻又討厭韭菜鍋貼。客人可以龜毛，但一定要有辦法賣給他

## 不准做的事

- 不准新增菜單沒有的品項
- 不准新增欄位或修改遊戲規則
- 不准改 `my-customers.json` 以外的檔案
- ★ 我自己加的禁止事項：不准寫誤導人的台詞。每句台詞都要如實反映那個情況，例如 too_expensive 的台詞要讓人看得出是嫌貴，not_on_menu 的台詞要說出他想吃的是哪一樣
- ★ 理由：台詞是店長推理的唯一線索。台詞騙人，遊戲就從推理變成瞎猜，跟同學交換客人包時也不公平
