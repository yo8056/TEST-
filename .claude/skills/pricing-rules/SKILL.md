# 定價心法

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一條都要寫「理由」。
> 填的內容來自你自己玩遊戲的經驗：哪些價格客人會買、哪些會嫌貴、星等怎麼變。

## 什麼時候用

AI 店長要決定某一天每樣菜的定價時。

## 一定要遵守的規則（來自規則書，不可以改）

- 定價只能在菜單的可定價範圍內（見 `web-lab/src/game/menu.js` 的 minPrice～maxPrice）
- 客人只有在「價格 ≤ 剩下的預算」時才會買
- 價格 ≤ 建議售價，客人買到第一順位才會「滿意」；滿意的人多，星等才會升

## 我的定價心法

★ 心法 1（例如：什麼時候該定在建議售價以下？）：第一版一律用建議售價，當作比較基準。之後要降到建議售價以下，必須有實際結果支持，例如試算結果出現「嫌太貴」的客人，或是想測試滿意度對星等的影響；每次降價都要寫出「每份少收多少元」。
★ 理由：沒有基準就看不出改動有沒有用。價格 ≤ 建議售價時，客人買到第一順位才會滿意，滿意比例決定星等，星等決定隔天來客數；但降價會犧牲單份收益，所以要有數字支持才降。（這是本次要驗證的策略假設，不是已經證明有效的經營規律。）

★ 心法 2（例如：什麼時候可以漲價？漲到多少？）：漲價只能在可定價範圍內，而且一次只動一樣菜、幅度寫清楚（例如 70 → 75）。漲價前先寫出可能的代價：超過客人預算就買不到、超過建議售價客人就不會滿意、星等下降後隔天來客變少。缺貨不能直接當成「漲價一定有效」的證據，缺貨先用補貨處理。
★ 理由：規則書寫明客人只在「價格 ≤ 剩下的預算」時才買，價格超過建議售價就拿不到滿意；漲價多收的錢可能被少賣的份數和掉的星等抵掉，要用試算結果比較才知道。（待驗證假設。）

★ 心法 3（自由發揮，例如：飲料和鍋貼要不要用不同策略？）：一次最多改 3 個明確設定，飲料和湯維持建議售價不漲。前幾天以「讓客人滿意、把星等撐住」為先，後幾天才考慮測試漲價；每次改價都和上一版用同一個客人包、同樣開局比較最終資金、星等、報廢。
★ 理由：飲料單份只賺十幾元，漲價多收有限，卻可能讓預算剛好的客人第二樣買不到；星等每 0.5 顆影響來客 10%，前面掉星後面幾天都受影響。一次改太多就分不出是哪個改動有效。（待驗證假設，要用自己的試算結果確認。）

## 回報格式

```text
第 N 天定價：
| 菜 | 定價 | 用了哪一條心法 |
```

## 不准做的事

- 不准定在可定價範圍以外
- 不准修改任何遊戲檔案
